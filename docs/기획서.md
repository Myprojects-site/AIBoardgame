# AI 보드게임 — 기획서 (초안)

> 친구들과 3D 테이블에 둘러앉아 미니 보드게임을 하는 웹사이트.
> 첫 게임은 조선 시전 상인을 테마로 한 확대 재생산 카드 게임 「한양 상단」(가제).
> 지시할 때 "기획서 4.3장대로"처럼 장 번호로 가리킨다.

---

## 1. 목표

- 링크 하나로 친구들이 들어와 **같은 테이블에 앉아 있는 느낌**으로 보드게임을 한다.
- 처음에는 게임 하나로 시작하고, 나중에 미니 보드게임을 계속 추가해 한 사이트에 모은다.
- 대상은 지인 2~4명이다. 공개 서비스, 결제, 랭킹은 만들지 않는다.
- 그림은 직접 만든다(바나나 프로 → 픽셀 아트). 코드는 Claude Code가 맡는다.

## 2. 사이트 구조

### 2.1 화면 흐름

```
입장(닉네임·내 색·프로필 사진 고르기) → 첫 화면(방 만들기 / 받은 링크로 들어가기)
  → 방(게임 고르기, 게임 설정, 자리 앉기, 준비) → 3D 테이블에서 게임 → 결과 → 다시 하기 / 로비로
```

- 회원가입 없이 닉네임만 쓴다. 브라우저에 임시 아이디를 저장해 새로고침해도 같은 사람으로 인식한다.
- 방은 초대 링크(`…/#/room/ABCD`)로 들어간다. 중앙 서버가 없어서 **공개 방 목록은 없다** — 방장이 링크를 카톡 등으로 보낸다.
- 자리가 다 차면 나머지는 구경꾼으로 들어온다.

### 2.1.1 방 만들기 설정

방을 처음 만든 사람이 방장이다. 방장의 브라우저가 판을 판정한다(2.4장). 방 만들기 창에서 아래를 고르고, 게임 시작 전까지는 방 안에서 바꿀 수 있다.

| 항목 | 고를 수 있는 값 | 기본 | 공통 / 게임별 |
|---|---|---|---|
| 게임 | 사이트에 있는 게임 | — | 공통 |
| 인원 | 게임이 허락하는 범위 (한양 상단은 2~4) | 4 | 공통 (범위는 게임별) |
| 튜토리얼 | 보여 주기 / 건너뛰기 | 보여 주기 | 공통 |
| 빈자리 | 비워 두기 / 봇으로 채우기 | 비워 두기 | 공통 |
| 차례 시간 제한 | 없음 / 1분 / 2분 / 3분 (넘기면 알림만, 자동 진행 없음) | 없음 | 공통 |
| 구경꾼 | 받기 / 안 받기 | 받기 | 공통 |
| 목표 점수 | 16 / 21 / 26 / 31 (31은 2~3인만) | 21 | 한양 상단 |

- 공통 항목은 사이트가, 게임별 항목은 규칙 모듈의 `options`가 정한다.
- 인원에 따라 못 고르는 값은 회색으로 막고 이유를 짧게 띄운다(예: "31점은 2~3인만"). 인원을 바꿔서 이미 고른 값이 막히면 기본값으로 되돌리고 알린다.
- 방 안과 초대 링크 미리보기에는 고른 설정이 요약으로 보인다(예: "한양 상단 · 4인 · 21점 · 튜토리얼").
- 방장은 지난번 설정을 기억해 두었다가 다음 방 만들기에서 그대로 채워 준다.

### 2.2 게임을 끼워 넣는 구조

게임 하나 = **규칙 모듈** + **테이블 구성** 두 덩어리. 사이트의 나머지(로비, 방, 접속, 아바타, 채팅, 소리)는 모든 게임이 같이 쓴다.

| 덩어리 | 하는 일 | 어디서 돈다 |
|---|---|---|
| 규칙 모듈 | 초기 상태, 할 수 있는 행동 목록, 행동 적용, 끝 판정, 플레이어별로 보여 줄 정보 | 방장 브라우저(판정), 모든 브라우저(미리보기) |
| 테이블 구성 | 3D 테이블에 무엇을 어디에 놓고 어떻게 움직이는지 | 클라이언트 |

규칙 모듈이 지켜야 할 모양:

```ts
interface GameRules<State, Action> {
  players: { min: number, max: number }                           // 인원 범위
  options: OptionSpec[]                                           // 방 설정에 띄울 항목 (예: 목표 점수)
  tutorial: TutorialStep[]                                        // 3.4장 튜토리얼 내용
  setup(players: PlayerId[], seed: number, options: Options): State
  legalActions(state: State, player: PlayerId): Action[]
  apply(state: State, player: PlayerId, action: Action): State   // 틀린 행동은 거부
  result(state: State): GameResult | null                        // 끝났으면 순위
  view(state: State, viewer: PlayerId | 'spectator'): unknown    // 숨긴 정보 가리기
}
```

### 2.3 기술

| 부분 | 선택 | 이유 |
|---|---|---|
| 클라이언트 | Vite + TypeScript + Three.js | 3D 테이블, 빠른 개발 서버 |
| 연결 | 브라우저끼리 직접 연결(WebRTC, PeerJS) | 게임 서버 없이 방장 브라우저가 판정. 처음 서로 찾을 때만 PeerJS 무료 중계 서버를 쓴다(가입 없음) |
| 규칙 | `packages/shared`에 순수 함수로 | 방장과 참가자 브라우저가 같은 코드를 쓴다. 그래픽 없이 테스트·봇 시뮬레이션 가능 |
| 저장 | 방장 브라우저(localStorage)에 판을 행동마다 저장 | 방장이 새로고침해도 판이 이어지게 |
| 배포 | **깃허브 페이지** (11/4 결정) | 화면 파일만 올리면 됨. 무료, 깃허브에 올리면(push) GitHub Actions가 자동으로 빌드·배포 |

```
보드게임/
  packages/shared/   규칙 모듈(게임별 폴더), 공용 타입
  client/            화면(Three.js 테이블, UI)과 연결(net/: 방장 판정·참가자 접속)
  assets/            최종 그림(픽셀 아트), 소리
  assets_src/        바나나 프로 원본 (게임이 읽지 않음)
  tools/             카드 표 만들기, 밸런스 시뮬레이션, 그림 정리
  docs/              기획 문서
```

### 2.4 온라인 동기화

게임 서버가 없다(깃허브 페이지는 화면 파일만 올릴 수 있다). 그래서 **방장 브라우저가 서버 역할**을 한다.

```
참가자 브라우저 ──"이 행동을 하겠다"──▶ 방장 브라우저 (규칙 모듈로 확인·적용)
                ◀──그 사람에게 보일 상태(view)── 
```

- 방장도 다른 참가자와 똑같이 "행동 요청 → 확인된 상태 받기"로 움직인다(방장 화면만 따로 만들지 않는다).
- 숨긴 정보(더미에서 몰래 찜한 카드, 더미 순서)는 `view()`로 가려서 보낸다. 방장 브라우저에는 판 전체가 있으므로 방장이 개발자 도구로 몰래 볼 수는 있다 — 친구끼리라 받아들인다.
- 참가자가 끊겼다 다시 들어오면 자기 자리로 돌아오고 현재 상태를 통째로 받는다. 차례인 사람이 2분 넘게 없으면 방장이 "기다리기 / 봇이 대신하기"를 고른다.
- **방장이 끊기면** 다른 사람 화면에 "방장을 기다리는 중"이 뜨고 판이 멈춘다. 방장이 같은 링크로 돌아오면(새로고침 포함) 저장해 둔 판으로 이어지고 참가자들은 자동으로 다시 붙는다.
- **방장이 "나가기"를 누르면** 판 전체를 다음 자리 사람에게 넘겨 그 사람이 새 방장이 된다. 창을 그냥 닫으면 넘길 수 없으므로 닫기 전에 확인 창을 띄운다.
- 방 코드가 곧 방장의 연결 주소다. 방장이 돌아와도 같은 코드를 다시 쓴다.
- 구현(2단계): 방 로직은 `packages/shared/src/room/host.ts`(연결과 무관, 테스트 가능), 연결은 `client/src/net/session.ts`. PeerJS 주소는 `aibg-<방 코드>`.
- 알려진 한계: 방장이 새로고침하는 순간 보낸 수는 사라질 수 있다(화면에 내 차례가 그대로 남아 다시 누르면 된다). 회사·학교처럼 엄격한 네트워크에서는 브라우저끼리 연결이 막힐 수 있다 — 지인 테스트에서 생기면 무료 TURN 중계 서버를 붙인다.
- 행동 기록을 남겨 결과 화면에서 다시 보기, 버그 재현에 쓴다.

## 3. 3D 테이블 — 같이 하는 느낌

### 3.1 공간

- 조선 게임의 방은 **한옥 사랑방**: 장판 바닥, 창호지 문으로 들어오는 빛, 가운데 낮은 상. 게임마다 방 꾸밈을 바꿀 수 있게 한다.
- 플레이어는 상에 둘러앉는다. 2인은 마주 보고, 3~4인은 둘러앉는다.
- 그림은 픽셀 아트 텍스처를 3D 판(카드, 토큰, 타일)에 붙인다. 텍스처 필터는 Nearest로 해서 도트가 번지지 않게 한다.
- 사람은 **프로필 사진 판**으로 앉는다(11/4 결정). 입장할 때 사진을 고르고(가운데를 정사각형으로 잘라 96px로 줄임), 안 올리면 기본 사진(내 색 바탕 실루엣), AI는 로봇 그림. 사진 판은 늘 카메라를 보고, 테두리는 내 색. 점수에 따라 **신분이 오른다**(3.5장).

### 3.2 카메라

- 기본은 내 자리에서 상을 내려다보는 시점. 다른 사람은 상 건너편에 앉아 보인다.
- 마우스 휠로 가까이·멀리, V 키로 "상 위에서 똑바로 내려다보기"를 켜고 끈다.
- **자유 시점**(F 키, 11/4 추가): 왼쪽 끌기 = 돌리기, 오른쪽 끌기 = 옮기기, 휠 = 확대. 너무 눕히지는 못한다(72°까지 — 더 눕히면 카드끼리 가려 누르기 어렵다). 다시 F를 누르면 내 자리 시점으로 돌아온다. 끌기는 누르기로 치지 않는다.
- 산 카드 더미 위에 장수, 물건 더미 위에 개수를 띄운다. 더미를 누르면 그 색 카드를 펼쳐 보는 창(장수·할인·점수)이 뜬다.
- 화면 아래 **내 살림** 막대: 색마다 "물건 수 +할인 수", 엽전, 물건 합계(10개 제한).

### 3.3 함께 있다는 신호

| 장치 | 내용 | 단계 |
|---|---|---|
| 차례 조명 | 차례인 사람 자리에 등잔불이 켜지고 아바타가 살짝 움직인다 | 필수 |
| 다른 사람 손 | 다른 사람이 가리키는 곳에 그 사람 색의 손 모양이 보인다 | 필수 |
| 들여다보기 | 누가 어떤 카드에 마우스를 올렸는지 보인다("○○이 이 카드를 보는 중") | 필수 |
| 움직임 | 토큰과 카드가 상 가운데에서 그 사람 자리로 실제로 날아간다 | 필수 |
| 소리 | 토큰 놓는 소리, 엽전 짤랑, 카드 넘기는 소리, 방 배경 소리 | 필수 |
| 반응 | 이모지 몇 개(웃음, 탄식, 박수, "에이~") → 아바타 머리 위 말풍선 | 필수 |
| 채팅 | 짧은 글 채팅, 아바타 머리 위에도 잠깐 뜸 | 필수 |
| 신분 변화 | 점수가 오르면 옷차림이 바뀐다 (3.5장) | 필수 |

음성 채팅은 넣지 않는다. 글 채팅만.

### 3.4 튜토리얼 (모든 게임 공통 틀)

글로 된 설명서 대신 **실제 3D 테이블 위에서 보여 주며** 가르친다.

**언제 나오나**
- 방장이 튜토리얼을 "보여 주기"로 두면, 게임 시작을 누른 뒤 첫 차례 전에 모두에게 나온다.
- 아는 사람은 "건너뛰기"를 눌러 기다린다. 다른 사람이 보는 동안 그 사람 자리에는 "튜토리얼 보는 중" 말풍선이 뜬다.
- 모두 끝내거나 건너뛰면 첫 차례가 시작된다. 방장은 "모두 건너뛰고 시작"을 누를 수 있다.
- 게임 중에도 메뉴에서 혼자 다시 볼 수 있다(판은 그대로 진행되고, 내 차례가 오면 알림).
- 사이트 첫 화면의 게임 소개에서도 혼자 볼 수 있다.

**보여 주는 방식**
- 테이블 위에 **연습용 판**을 깔아 둔다. 실제 판과 똑같이 생겼지만 결과가 실제 판에 남지 않는다.
- 단계마다:
  - 카메라가 설명할 곳으로 천천히 다가간다.
  - 그곳만 밝고 나머지는 어둡게 한다.
  - 붓글씨 느낌의 화살표와 짧은 글(두 줄 이내)을 띄운다.
  - 안내 캐릭터(예: 주막 주인)가 말풍선으로 말한다.
- **직접 해 보기 단계**에서는 정해진 행동(예: "청자·비단·인삼을 하나씩 가져와 보세요")을 해야 다음으로 넘어간다. 틀리면 무엇이 틀렸는지 알려 준다.
- 버튼: 이전 / 다음 / 건너뛰기. 진행 점(●●●○○)으로 남은 단계를 보여 준다.
- 한 게임 튜토리얼은 **5단계 이하, 1분 안쪽**으로 한다. 직접 해 보기는 2번까지.
- 튜토리얼에는 판을 시작하는 데 꼭 필요한 것만 넣는다. 나머지 규칙은 **게임 중 팁**으로 돌린다: 그 상황이 그 사람에게 처음 생길 때 해당 자리 옆에 한 줄로 잠깐 뜬다(예: 물건이 10개를 넘을 때). 팁은 판마다 사람마다 한 번만 나오고, 튜토리얼을 건너뛴 사람에게는 나오지 않는다.

**만드는 방식**
- 튜토리얼 단계는 규칙 모듈의 `tutorial`에 데이터로 적는다. 어떤 판 상태를 깔지, 카메라를 어디에 둘지, 무엇을 밝힐지, 안내 글, 기다릴 행동이 들어간다. 그러면 새 게임을 붙일 때 데이터만 쓰면 된다.

```ts
interface TutorialStep {
  board: string            // 깔아 둘 연습 판 상태 이름
  focus: string[]          // 밝힐 물건 (예: ['market.tier1', 'supply.cheongja'])
  camera?: string          // 카메라 위치 이름
  text: string             // 안내 글 (두 줄 이내)
  guide?: string           // 안내 캐릭터 말풍선
  waitFor?: ActionPattern  // 직접 해 보기: 이 행동을 해야 넘어감
}
```

### 3.5 신분 아바타

모두 천민으로 시작해서 점수가 오를수록 옷차림이 바뀌고, 이긴 사람은 왕이 된다.

| 신분 | 언제 | 보이는 곳 |
|---|---|---|
| 천민 | 시작 | 사진 아래 이름표 "[천민] 이름" |
| 상민 | 목표 점수의 25% | 〃 |
| 중인 | 50% | 〃 |
| 양반 | 75% | 〃 |
| 왕 | 판이 끝나고 1등 | 사진 테두리가 금테, 위에 👑 |

옷차림이 바뀌는 아바타는 11/4에 프로필 사진으로 바꾸면서 뺐다.

- 신분이 오르는 순간 그 자리에 빛과 소리, 머리 위 글씨("○○ 중인이 되었다!")를 띄운다.
- 사람마다 **내 색**(입장할 때 고름)을 사진 테두리와 이름표에 칠해 구별한다.
- 결과 화면: 1등 사진은 금테와 관, 알림 "👑 ○○님이 왕이 되었다!".
- 신분 기준은 "점수 ÷ 목표 점수"라서 점수가 있는 다른 게임도 같은 아바타를 쓸 수 있다. 점수가 없는 게임은 게임이 진행도를 알려 준다.

## 4. 첫 게임 「한양 상단」(가제) 규칙 초안

> 조선 시전의 상인이 되어 오방색 물건을 사고팔며 거래처를 늘리고, 이름난 인물들의 방문을 받아 가장 큰 상단이 된다.
> 아래 수치는 모두 **초안**이다. 4.6장의 시뮬레이션으로 확정한다.

### 4.1 물건(자원) — 오방색

| 물건 | 색 | 
|---|---|
| 청자 | 청 |
| 비단 | 적 |
| 인삼 | 황 |
| 한지 | 백 |
| 먹 | 흑 |
| 엽전(상평통보) | 만능 — 어떤 물건으로도 쓸 수 있다 |

물건 토큰 수: 2인 5개, 3인 6개, 4인 7개씩. 엽전 5개.

뒷자리 시작 물건: 선 플레이어가 유리해서 뒷자리는 물건을 1개 쥐고 시작한다(색은 무작위로 서로 다르게, 엽전은 안 줌).

| 인원 | 차례 순서대로 시작 물건 |
|---|---|
| 2 | 0, 1 |
| 3 | 0, 1, 1 |
| 4 | 0, 0, 1, 1 |

### 4.2 거래처 카드

| 단계 | 이름 | 장수 | 점수 | 느낌 |
|---|---|---|---|---|
| 1 | 장터 | 35 (색마다 7) | 0~1 | 행상, 주막, 대장간, 장터 국밥집 |
| 2 | 공방 | 30 (색마다 6) | 1~3 | 도공, 직조 공방, 지물전, 인삼 밭 |
| 3 | 대상단 | 20 (색마다 4) | 3~5 | 육의전, 조운선, 왜관 무역, 의주 상단 |

- 처음엔 75장(공방 25, 대상단 15)이었는데, 4인 26점에서 카드가 떨어지는 판이 20%라 85장으로 늘렸다.

- 카드마다 **한 가지 색의 할인**을 준다. 그 색 물건이 영구히 1개 있는 것처럼 계산된다.
- 각 단계 4장씩 공개해 둔다.
- 카드 표(비용·점수·할인색)는 원작 표를 쓰지 않고 `tools/`의 스크립트로 새로 만든다. 만드는 규칙: 점수 1점당 비용 예산, 단계별 비용 합 범위, 색 분포 균형. 카드 id를 고정해서 그림 파일 이름과 맞춘다.

### 4.3 명사(名士) 방문 타일

- 조선의 이름난 인물이 상단을 찾아온다. 인원 + 1장을 공개한다.
- **조건은 할인 카드 수**로, 모양을 여러 가지로 둔다. 어려울수록 점수가 높다(2~4점).
- 실제 값은 `packages/shared/src/hanyang/data/patrons.ts`. 시뮬레이션 뒤 값(괄호는 나온 판 중 데려간 비율):

| 명사 | 조건 | 점수 |
|---|---|---|
| 장영실 | 흑 4, 청 3 | 2 (76%) |
| 허준 | 황 5, 백 2 | 2 (35%) |
| 김홍도 | 백 3, 적 3, 흑 2 | 2 (97%) |
| 신사임당 | 다섯 색 각 2 | 2 (99%) |
| 정약용 | 백 4, 청 2, 황 2 | 3 (86%) |
| 김만덕 | 황 5, 적 3 | 3 (38%) |
| 박지원 | 적 4, 흑 3, 청 2 | 3 (81%) |
| 한석봉 | 흑 5 | 3 (40%) |
| 황진이 | 적 5, 백 3 | 4 (41%) |
| 안견 | 청 5, 백 3, 흑 2 | 4 (38%) |
- 차례가 끝날 때 조건을 채운 명사가 있으면 하나를 골라 데려온다(행동을 쓰지 않음).

### 4.4 차례에 하는 일 (넷 중 하나)

**차례 순서는 시작할 때 주사위로 정한다**(11/4 결정, 모든 게임 공통 `core/dice.ts`). 모두 하나씩 굴려 높은 눈부터, 같은 눈끼리는 그 사람들만 다시 굴린다. 상에도 그 순서대로 둘러앉는다. 화면에서는 각자 자리에서 주사위가 굴러 떨어지고 "차례: ○ → ○ → ○" 알림과 채팅이 뜬다. 뒷자리 시작 물건(4.1장)은 이 순서를 따른다.


1. **물건 사들이기**: 서로 다른 물건 3개를 가져온다.
2. **한 물건 몰아 사기**: 같은 물건 2개를 가져온다. 그 물건이 4개 이상 남았을 때만.
3. **외상 장부**: 공개된 카드나 더미 맨 위 카드 1장을 찜해 손에 두고 엽전 1개를 받는다. 손에는 3장까지.
4. **거래 성사**: 공개된 카드나 찜한 카드를 산다. 비용에서 할인을 빼고 나머지를 물건·엽전으로 낸다.

- 차례가 끝날 때 물건이 10개를 넘으면 10개가 될 때까지 되돌려 놓는다.

### 4.5 끝

- 방장이 방 설정에서 **목표 점수**를 고른다: 16 / **21(기본)** / 26 / 31점. 31점은 2~3인만 고를 수 있다.
- 누군가 목표 점수에 닿으면 그 바퀴를 끝까지 돌고 끝낸다.
- 단계 더미 두 개가 비고 공개 카드도 다 팔리면 목표에 못 닿아도 그 바퀴를 마치고 끝낸다. 26·31점에서 카드가 모자랄 수 있어서 둔 규칙이다.
- 점수가 가장 높은 사람이 이긴다. 같으면 산 카드가 적은 사람이 이긴다.

봇 시뮬레이션 결과 (한 사람당 차례 평균, 판마다 300판). 실제 시간은 한 차례 20초로 어림한 값.

| 목표 점수 | 2인 | 3인 | 4인 | 4인 실제 시간 | 4인 카드 소진으로 끝난 판 |
|---|---|---|---|---|---|
| 16 | 25 | 24 | 24 | 약 30분 | 0% |
| 21 | 27 | 26 | 26 | 약 35분 | 0% |
| 26 | 29 | 28 | 27 | 약 37분 | 5% |
| 31 | 31 | 30 | (막음) | — | (30%라 막음) |

- 목표 점수를 올려도 판이 크게 길어지지 않는다. 뒤로 갈수록 할인이 쌓여 점수가 빨리 붙기 때문이다.
- 카드 표와 명사는 모든 목표 점수가 같은 것을 쓴다. 점수별로 표를 따로 만들지 않는다.
- 4인 31점은 카드가 떨어져 끝나는 판이 30%라서 고를 수 없게 했다(11/4 결정). 수치는 `RULES.targetPlayers`.
### 4.6 밸런스 확인

그래픽 없이 규칙 모듈만으로 봇끼리 수천 판을 돌려서 아래를 본다.

- 한 판 길이: 목표 점수마다 4.5장 표 범위 안에 드는지 (16·21·26·31점, 2~4인 전부)
- 26·31점에서 카드가 떨어져 목표 전에 끝나는 판이 몇 %인지
- 먼저 하는 사람의 승률이 지나치게 높지 않은지
- 안 팔리는 카드, 너무 쉽거나 아무도 못 데려가는 명사가 없는지
- 한 색만 모으는 전략이 늘 이기지 않는지

실행: `npm run sim -- 300`. 첫 결과(11/4)와 고친 것:

| 문제 | 고친 것 | 결과 |
|---|---|---|
| 2인 선 플레이어 승률 61% | 뒷자리 시작 물건(4.1장). 엽전 1개는 지나쳐서(선 35%) 물건 1개로 | 2인 47~53%, 3인 27~37%, 4인 17~33% |
| 4인 26·31점 카드 소진 30%·67% | 공방·대상단 색마다 1장씩 더 (85장) | 5%·30% |
| 5점 대상단이 3점보다 6배 덜 팔림 | 비용 6+5 → 6+4 | 3배 덜 팔림. 비용이 두 색에 몰려 봇이 덜 노림. 사람 테스트에서 다시 본다 |
| 한석봉·황진이 7~8%, 신사임당·김홍도 거의 100% | 한석봉·황진이 조건 낮춤, 신사임당·김홍도 2점으로 | 35~41% / 쉬운 둘은 점수를 낮춰 둠 |
| 한 색 몰기 | (고칠 것 없음) | 색마다 24~29% (기대 25%) |

봇은 사람보다 단순하게 두므로, 위 수치는 기준선이다. 지인 테스트(6장 7단계)에서 다시 맞춘다.

### 4.7 선택 규칙

넣지 않는다(11/4 결정). 장날·관청 허가 같은 변주 없이 4.4장 규칙만 쓴다.

### 5.1 3D 모양을 좋은 것으로 바꾸기 (토큰, 주사위)

사람은 프로필 사진이라 모델이 필요 없다(3.1장). 토큰·주사위는 기본 도형이다. 모양은 모두 `client/src/games/hanyang/models.ts` 한 파일에서 만들므로, 바꿀 때는 이 파일만 고치면 테이블 코드는 그대로다.

| 방법 | 무엇을 준비하나 | 장단점 |
|---|---|---|
| **A. 픽셀 그림 세운 판** (3.1장 원래 계획, 추천) | 신분 5장 × 앉은 모습 PNG (배경 투명, 48×64 등). 토큰 윗면 그림 6장 | 바나나 프로로 바로 만들 수 있고 카드 픽셀 아트와 그림체가 맞는다. 옆에서 보면 납작하다 |
| **B. 3D 모델 파일 (.glb)** | 아래 조건의 모델 파일 | 입체감이 가장 좋다. 모델을 구하거나 만드는 품이 든다. 픽셀 카드와 그림체를 맞춰야 한다(로우폴리 + 도트 텍스처 추천) |

B로 갈 때 모델 조건:
- 형식 **glTF 바이너리(.glb)**, 위쪽이 +Y, 바닥이 원점, 앉은 사람 키 2.5~3 정도(달라도 코드에서 맞춤).
- 파일 하나 2~5MB 이하, 텍스처 1024px 이하, 인물 하나 1~2만 삼각형 이하 (친구 노트북에서도 가볍게).
- 신분 5종: 모델 5개, 또는 몸 하나 + 모자·옷 5종. **띠(내 색) 부분은 재질 이름을 `sash`로** 해 두면 코드가 사람마다 색을 바꾼다.
- 토큰: 동전 모델 하나(색은 코드가 칠함) 또는 색별 6개.
- 움직임(손 흔들기, 절하기)을 넣으려면 모델 안에 애니메이션을 넣어 둔다.

B의 모델 구하는 곳: 직접 만들기(Blender), AI 3D 생성 서비스(그림 → 3D 모델), 에셋 상점(Sketchfab, itch.io 등 — **라이선스 확인**).
파일을 `client/public/models/`에 넣고 알려 주면, `models.ts`를 파일을 불러오는 방식으로 바꾼다(불러오는 동안은 지금 도형을 보여 준다).

## 6. 개발 단계

한 단계 = 한 번의 작업 세션. 끝날 때마다 실행해서 확인하고 커밋한다.

| 단계 | 만들 것 | 확인 방법 |
|---|---|---|
| 1 | 프로젝트 뼈대, 규칙 모듈, 카드 표 생성, 봇 시뮬레이션 | 봇끼리 1000판, 4.6장 기준 확인 |
